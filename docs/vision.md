# PureGit 中心思想（产品定位 · v0.0.1 新概念）

> 本文档是全项目**最高纲领**，定义「做什么、为什么、做成什么样」。
> 所有子文档（design / architecture / api-compat / tasks / plan / 规范 / prompt）均以此为准绳对齐；
> 任何新增功能、UI 决策、技术取舍，先对照本文档再动手。
>
> **v0.0.1 新概念（2026-08-12 定稿）**：本项目由「全面复刻**简版** GitHub」升级为「**全量复刻** GitHub」——
> 功能完成度对齐官方（分批推进，见 `tasks.md` 路线图）；「简约」不再作为范围取舍判据，仅保留为
> **前端 UX 原则**（页面干净整洁、操作由繁化简）。中心思想一句话：**用官方 API 全量复刻 GitHub 前端**。

## 一句话定位

> **通过 GitHub 官方 API，全量复刻 GitHub 前端；功能完成度以官方页面为基准（分批对齐），
> 界面保持干净整洁、操作由繁化简。**（简约 = 前端体验，不再是功能范围。）

## 三个支柱

### 1. 全量（Full Coverage）—— 功能完成度对齐官方

不满足于「核心闭环」，而是以**官方页面为基准**逐页复刻：官方有的页面 / 模块 / 功能，原则上都应具备
（按依赖层级 L0→L5 分批推进，详见 `tasks.md` 需求基线与 `plan.md` 路线图）。

| 层级 | 覆盖方向 | 现状（v0.0.1 基线） |
|------|----------|---------------------|
| **L0 基础设施** | API 封装（Octokit SDK 统一封装、GraphQL/REST 双通道冗余熔断）、布局（PageLayout 三栏模型）、组件（shadcn/ui） | ✅ 完成 |
| **L1 公共组件** | 代码展示（高亮/行号）、Diff、Markdown 编辑器、回复/评论等跨页组件 | ✅ 完成 |
| **L2 全局页** | 首页 Dashboard、搜索、全局 Issues/Pulls、通知、Gist、`/$debug` API 调试面板 | ✅ 完成（调试面板为本项目自研增值） |
| **L3 用户级** | 用户主页、组织主页、个人设置（资料/账号/邮箱/组织/仓库/外观/权限） | ✅ 完成（复刻简化版 → 分批对齐官方） |
| **L4 仓库核心** | Code（树/blob/编辑）、Issues、Pulls、Releases、Actions、Security、Insights、Wiki、Projects、仓库设置 | ✅ 核心完成（深度子页分批对齐） |
| **L5 深度功能** | 评审工作流、Packages、Webhooks、Pages 托管、多账号等**曾被排除的高级功能** | ⏳ **分批推进**（评审工作流 ✅ 已完成 2026-08-12；其余按路线图） |

> **实现现状**：L0~L4 核心已闭环（浏览/协作/账户/CLI）；L5 深度功能（代码评审工作流、Packages、
> Webhooks、Pages 托管等）从 v0.0.1 起**分批纳入**——按官方页面层级与依赖关系排序，见 `tasks.md` / `plan.md`。

> **未登录访问策略**：仅开放仓库 Code 浏览（根/tree/blob/new/edit）；其余仓库 tab 切换时内容区显示
> 登录墙（LoginPrompt + 聚光灯动画指引登录，URL 驱动、登录后回落）。首页/搜索/用户主页保持匿名可浏览。

### 2. 前端简洁（Clean UX）—— 简约仅限体验层

「简约」不再决定**做什么**（那是全量复刻的范围），只决定**怎么做**：

- **页面干净**：统一宽度（max-w-6xl）、统一间距、统一组件（shadcn/ui）、信息密度适中，无广告无干扰
- **操作化简**：高频操作一步直达（star / fork / 创建 issue 在详情页直接可用）；导航符合 GitHub 心智模型
  （仓库 tab、设置左侧导航）；引入新功能时**不做官方页面的繁复交互堆叠**，保留官方信息骨架、砍掉视觉噪音
- **技术化简**：Octokit SDK 统一封装 + 用户可选主模式（GraphQL 优先 / REST 优先），双额度自动冗余，页面组件不感知协议细节

> **复刻取舍判据（全量 × 简洁的平衡）**：功能**做全**（对齐官方页面），呈现**做简**（官方布局骨架 +
> 干净组件 + 一步直达交互）。当官方功能本身是复杂工作流（如评审、CI 配置）时，按官方交互复刻，不自行删减步骤。

### 3. 真实（Authentic）—— 一切数据来自官方 API

- 全部数据经 GitHub 官方 API（Octokit SDK 统一封装，主模式用户可选、双额度自动冗余），不造假数据
- 双端点 API 一律 smart 包装（GraphQL 首选 + REST 降级），实现**冗余熔断**（详见 `architecture.md` 与 `api-compat.md`）
- CLI 集成：git 镜像端点自动代理 clone / pull / push（insteadOf 一行配置接入）

## 设计原则（映射到开发）

| 原则 | 落地要求 |
|------|----------|
| 全量 | 功能清单见 `tasks.md`（需求基线）与 `plan.md`（路线图）；新增功能先对照官方页面是否缺失，缺失即入路线图 |
| 简洁（UX） | 页面复用 shadcn/ui；布局遵循 GitHub 心智模型；交互一步直达；**「做简」仅限呈现层，不限功能范围** |
| 真实 | 一切数据来自官方 API（Octokit 统一封装，双通道冗余），不造假数据 |
| 辅助 | **API 对照索引 + 页面分类索引**（`scripts/` 内部工具 + `scripts/data/*.json`）是开发辅助基线——查接口/查页面/查关联用工具，不靠记忆 |

## 验收视角（面向最终用户的一句话）

> 「一个功能对齐官方、界面干净整洁、登录后能看、能搜、能管（issue/PR/star/fork/评审/设置）、
> 能 clone/pull/push 的 GitHub 前端复刻。」
